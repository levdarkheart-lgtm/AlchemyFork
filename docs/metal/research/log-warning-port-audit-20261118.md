## Native and inherited defects found

**PPD-467, native worker recovery:** worker creation previously dropped its bool; void publication completion discarded failure and finalized raw data even after cancel. Synchronous native upload already retained/retried. The repair forwards both creation and publication results, retains decoded pixels and old published generation on failure, requeues with original age and balanced ownership, and finalizes only success. Publication already settled before worker continuation retains its result; a new no-work upload does not inherit stale failure. This source defect is **not proved to have happened in69277** and cannot explain a remote403 response that stopped before upload.

**PPD-468, inherited certificate dates:** actual CertExpired is immediately followed by trust-bundle scan120good/rejected1. Original and staged bundle bytes match; OpenSSL independently finds121valid at the recorded timestamp. Its single GeneralizedTime certificate has validity2011–2046; the old helper treats20461006083956Z as two-digit year20/month46 and normalizes the end date into2023. Native Metal did not introduce this parser. Repair uses validated ASN1_TIME_to_tm, preserving UTC and standard1950/2049 UTCTime pivot, rather than changing trust policy or the bundle.

**PPD-469, inherited invalid-date boundary:** peer review found that failed date conversion's existing epoch sentinel could still be inserted as valid metadata. A malformed notBefore with valid future notAfter could pass the old range check. The separate narrow metadata guard preserves invalid-field absence so existing validation rejects it, while a legitimately encoded Unix epoch remains a valid date. No malformed endpoint certificate was observed in this run.

All three were registered before repair in [the defect register](../POST_PORT_DEFECTS.md). Build/test outcomes and owner acceptance remain separate.
